# Marketa Complete User’s Manual

## Deliverable
Create an editable Microsoft Word document named `marketa_users_manual.docx`, suitable for inclusion as a capstone appendix. The document will use a formal academic tone, numbered headings, page numbers, a Table of Contents, consistent terminology, and screenshot placeholders that can be replaced later.

## Documentation approach
- Document only behavior confirmed in the current Marketa application.
- Use the exact names of pages, buttons, tabs, statuses, and messages shown in the interface.
- Explain each task in simple numbered steps for readers with no technical background.
- Distinguish buyer, seller, and administrator instructions.
- Describe Marketa’s actual seller-contact and proposal-based transaction flow instead of claiming unsupported cart, online payment, shipping, stock, shop, or earnings functions.
- Clearly label unsupported requested functions as “Not currently available” where readers would reasonably expect them.
- Add `[Insert Screenshot: …]` placeholders after every major screen or critical action, with concise captions and suggested screenshot subjects.

## Manual structure

### Front matter
- Title page with document title, system name, capstone-project placeholders, version, and date.
- Document-control table with placeholders for authors, institution, adviser, approval, and revision history.
- Table of Contents generated from Word heading levels.
- List of screenshot placeholders for easier image collection.

### 1. Introduction
- Purpose and scope of the manual.
- Overview of Marketa as a verified person-to-person buy-and-sell marketplace.
- Intended users: buyers, sellers, and administrators.
- System requirements: supported modern browser, desktop/mobile device, camera access for verification, email access, and reliable internet.
- Important transaction and safety limitations.

### 2. Getting Started
- Account registration and legal-agreement acceptance.
- Eight-digit email verification.
- Identity-document upload, data extraction, liveness check, and administrator review.
- Six-digit MPIN setup.
- First-time Welcome screen.
- Login and automatic account-status handling.
- Eight-digit password-recovery code, verification, and new-password creation.
- Common verification states and what the user should do next.

### 3. Navigating Marketa
- Header, marketplace link, search, category navigation, notifications, Inbox, Sell, Saved, Transactions, Profile, Settings, and Log out.
- Mobile and desktop navigation differences.
- Explanation that Marketa uses shared marketplace access rather than separate Buyer and Seller modes; a verified user can perform either role.
- Restriction and account-status notices.

### 4. Buyer’s Guide
- Browse the marketplace.
- Search and filter listings by the controls actually available.
- Open item details and seller information.
- Save and remove favorite listings.
- Contact a seller and use the Inbox.
- Review a proposal and follow transaction statuses.
- Confirm a completed exchange.
- Cancel an eligible transaction.
- Leave a rating only after a completed transaction.
- Report or appeal where supported.
- State clearly that cart checkout, in-app payment, delivery/shipping, and formal returns are not currently available; arrangements occur through messaging and the transaction workflow.

### 5. Seller’s Guide
- Explain that a user profile serves as the seller identity; there is no separate shop setup.
- Create a listing using the actual photo, title, price, description, condition/category, and other available fields.
- Review image and listing requirements.
- Edit or remove a listing where supported by the current interface.
- Respond to buyer messages.
- Create and manage a transaction proposal.
- Mark the seller’s part of an exchange as completed and monitor buyer confirmation.
- Cancel an eligible transaction.
- View transaction history and ratings.
- Appeal an unfair or malicious review.
- State clearly that stock tracking, shipping fulfillment, payment settlement, and earnings reports are not currently available.

### 6. Messaging and Transactions
- Search existing conversations and start contact from a listing or profile.
- Send text and supported media.
- Edit or unsend messages where available.
- View listing context and participant profiles.
- Explain each transaction status in plain language: proposed, agreed, discussion, seller completed, completed, and cancelled.
- Provide separate buyer and seller completion instructions.
- Explain cancellation effects and system notices.
- Explain appeal-chat consent and the time-limited administrator-access rule.

### 7. Reviews, Ratings, Appeals, and Safety
- Eligibility to submit a review.
- Rating and written-feedback procedure.
- Viewing rating summaries and review history.
- Seller appeal procedure for disputed reviews.
- Dual-consent chat review and privacy implications.
- Account restriction or suspension notices and submitting an appeal.
- Safe trading reminders aligned with the actual application.

### 8. Account Management and Security
- View and edit permitted profile information.
- Explain that the verified display name is locked to identity-verification records.
- Change or reset the MPIN using the password and eight-digit email code.
- Notification settings actually available in Settings.
- Privacy, legal documents, and security controls actually available.
- Account deactivation: duration choices, visibility effects, logout, and automatic reactivation.
- Account deletion: immediate deletion versus 30-day grace period, consequences, cancellation/restoration, and permanent-data effects.
- State clearly if saved addresses or payment methods are not part of the current system.

### 9. Administrator’s Guide
- Administrator access and dashboard orientation.
- Verification-submission queue, OCR fields, identity media, liveness evidence, approval, and rejection.
- User/account oversight available in the dashboard.
- Listing or report handling available in the dashboard.
- Review-appeal workspace, evidence review, dual-consent chat access, and resolution.
- Behavioral monitoring: risk scores, alerts, review states, restrictions, and suspensions.
- Audit logs: searching, filters, record details, integrity checks, and export.
- Dashboard statistics and available analytics, without claiming unsupported reports.
- Privacy and least-access responsibilities for administrators.

### 10. Troubleshooting and Frequently Asked Questions
Use a problem–possible cause–solution format for:
- Registration and email-code issues.
- Login and password-reset issues.
- Camera, ID scan, OCR, and liveness difficulties.
- MPIN failure, lockout, and reset.
- Listing-photo or listing-submission problems.
- Missing messages, notifications, saved items, or transaction updates.
- Proposal, completion, cancellation, rating, and appeal issues.
- Deactivated or deletion-pending accounts.
- Browser, connection, and permission problems.
- Contact/support instructions using only contact details present in the application; otherwise provide a clearly marked institutional placeholder.

### 11. Glossary
Define all important terms used by the application, including listing, seller, buyer, saved item, inbox, proposal, transaction, completed transaction, MPIN, OTP/email code, KYC, OCR, liveness check, verified account, appeal, restriction, suspension, audit log, and deletion grace period.

### Appendices
- Quick-reference task table.

- Account-status and verification-status reference.
- Screenshot checklist keyed to all placeholders.

## Word-document design
- Use US Letter size, one-inch margins, an accessible professional font, restrained Marketa-aligned blue accents, and black body text.
- Use Word heading styles so the Table of Contents can be refreshed after editing.
- Use numbered lists for procedures and properly formatted bullet lists for notes.
- Use compact tables for requirements, troubleshooting, status references, and document control.
- Add headers and footers with the manual title, version placeholder, and page number.
- Keep screenshot placeholders visually distinct, consistently captioned, and large enough to replace with actual images.
